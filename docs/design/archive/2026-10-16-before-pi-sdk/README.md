## 共享上下文：七层模型

后续所有设计都挂在这张图上。

```
        ┌──────────────────────────────────────────────┐
        │ L5 治理面（横切所有层）                       │
        │   权限 · 凭据 · 限频 · 退避 · 审计            │
        └──────────────────────────────────────────────┘
   人 ──►
        ┌──────────────────────────────────────────────┐
        │ L0 状态层                                     │
        │   会话 / 任务 / 目标 / 记忆 / 用户模型         │
        │   ← 「session 上云」= 这一层；多端是它的薄视图  │
        └──────────────────────────────────────────────┘
                  │ 读状态
        ┌──────────────────────────────────────────────┐
        │ L1 触发层                                     │
        │   时间 / 事件 / 状态变化 / 自省                │
        │   产出：候选（不是消息）                       │
        └──────────────────────────────────────────────┘
                  │ 候选
        ┌──────────────────────────────────────────────┐
        │ L2 判断层  ★核心                              │
        │   值不值得说 + 走哪一档                        │
        │   产出：Decision{档位, 分数, 理由} + 裁决记录   │
        └──────────────────────────────────────────────┘
                  │ 被批准的候选
        ┌──────────────────────────────────────────────┐
        │ L3 执行层                                     │
        │   真正干活：调 API / 操作浏览器 / 生成内容      │
        └──────────────────────────────────────────────┘
                  │ 结果
        ┌──────────────────────────────────────────────┐
        │ L4 投递层                                     │
        │   送到你面前：push / digest / feed / 会话      │
        │   ← 主要工作是决定不送                         │
        └──────────────────────────────────────────────┘
                  │
                人 ──反馈──► L6 反馈层 ──► 更新 L0 用户模型 ──► 回到 L2
```

### 哪层需要模型

| 层 | 需要模型 | 能力需求 |
|---|---|---|
| L0 状态 | ❌ | — |
| L1 触发 | ⚠️ 仅「自省」类 | 弱 |
| **L2 判断** | ✅ | **弱**（判断相关性，不需要多步推理） |
| **L3 执行** | ✅ | **强**（拆解任务、操作工具、生成内容） |
| L4 投递 | ❌ | 纯工程 |
| L5 治理 | ❌ | 纯工程 |
| L6 反馈 | ❌ | 纯工程 |

**只有两层需要模型，而且能力档位完全不同。不要用同一档模型干这两件事。**

### 三个横切面

| 横切面 | 覆盖 | 为什么必须横切 |
|---|---|---|
| **可替换** | L1 触发源 / L2 判断器 / L3 执行器 / L4 渠道 | **L2 尤其必须**——没有可替换的判断器就没有 A/B，无法证明指标变好 |
| **审计** | 所有层，尤其 L2 的「沉默」 | 记「为什么没说」。全行业空白 |
| **可重放** | 事件流 → L1~L4 | 让判断可回归测试；时间可被外部推进 |

### 三条不能划错的边界

1. **L1 产出「候选」不是「消息」**——触发 ≠ 开口。触发器一旦直接发消息，L2 就永远没机会判断。
2. **L2 必须能输出「无」**——默认档是 DIGEST，不是 SPEAK_NOW。
3. **L4 不是 L2 的被动执行者**——L2 说「值得说」，L4 还要回答「现在送到吗、送到哪个设备、要不要合并」。**两层判断，不是一个。**

## Pi 覆盖对照（已定平台：`pi-durable`）

| 层 | Pi 给了什么 | Point 要做什么 |
|---|---|---|
| L0 会话/任务/文档 | ✅ 原子 commit + entry/document 双模型 + fork | — |
| L0 持久化 | ✅ SQLite / JSONL / Memory + 迁移机制 | 用 SQLite |
| L0 崩溃恢复 | ✅ `resume()` + 每 phase checkpoint + intent/effect/outcome | — |
| L0 上下文 | ✅ **`head` + `ContextEdit`**（投影不改存储） | — |
| **L0 记忆** | ❌ 只有 document + 会话内摘要 | **外挂**（`MemoryAdapter`，可替换）|
| **L1 触发** | ❌ 零 cron | **自建**（`sleep` + `env.watch` + `submit`） |
| **L2 判断** | ⚠️ 骨架（`models.classify()`） | **策略 + 特征 + 预算** |
| L3 执行 | ✅ pi-ai(95 provider) + 工具 + nested call + env | —（不加沙箱）|
| **L4 投递** | ❌ 仅进程内回调 | **全自建**（`type:"write"` 是现成通道） |
| **L5 治理** | ❌ 整个生态都没有 | **✅ 不做权限层**（完全权限，与 Pi 哲学一致） |
| L6 反馈 | ⚠️ 一半（usage/cost） | **评估 + 反馈闭环** |

**三条硬约束**：单进程 · 无沙箱 · 无调度 → 详见 [runtime-selection.md](runtime-selection.md)
