# 记忆层与插件适配

> 保留：记忆自托管、实现可替换、用户可读可纠正。切换 Pi SDK 后，优先检查生态集成，不绑定旧 durable extension 路径。

## 选型边界

记忆服务必须能自托管；推理服务是否远程调用是另一个问题。不能因“有 Dockerfile”就推断所有功能都可自托管，也不能因“自托管”就推断数据不会调用远程模型。

既有调研中的 OpenViking、腾讯 TencentDB-Agent-Memory、mem0 等仍是候选，不代表已经选定、安装或验证。历史候选对比保存在[旧版文档](../2026-10-16-before-pi-sdk/memory-adapter.md)，其中版本、功能和兼容性需按实际接入重新核实。

具体实现优先采用现成 SDK 插件或自托管适配。纯文件/SQLite 兜底是候选，不再要求先完整自建一个记忆框架才能试外挂。

## Point 的契约（草案）

| 能力 | 期望 |
|---|---|
| 写入/召回 | 接受 Point 的事实结构，返回内容及可用来源 |
| 查看/修订 | 用户能查看和纠正，修订不会被后台无声覆盖 |
| 遗忘/删除 | 回报具体处理范围及限制，而不是仅返回成功布尔值 |
| 画像/索引 | 为主/子 session 提供小规模上下文，具体方法待选型 |
| 健康/迁移 | 可识别后端失败；替换时有数据导出/导入或重建路径 |

预留字段：`source_ref`、`asserted_by`、`valid_from`、`valid_until`、`superseded_by`、`confidence`。字段为空要显式表达未知，不能伪造来源。

接口可替换不意味着数据无成本迁移。ID、来源引用、修订记录和删除状态的迁移也是选型条件。

## 失败与数据处理

记忆不可用时主对话可以降级工作，但要区分“查不到”和“服务失败”。涉及已知约束的任务不能把服务失败直接当成没有约束。

凭据、模型端点及数据出口需明确配置和记录；按已确认的产品范围，不引入旧方案中的 taint/egress 审批系统。若未来改变该范围，需要显式重新决策。

## 待验证

先验证一个候选的无终端 SDK 接入、任务间使用、用户修订和重启恢复，再决定实现。来源、完整删除和回检的不足必须写明，不能以占位字段当成功能已完成。
