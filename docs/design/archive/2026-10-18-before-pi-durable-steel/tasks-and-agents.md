# 任务、目标与子 Agent

> 主/子 Agent 协作与按任务生命周期已定；Goal 的具体模型和插件方案待验证。

## 四个概念

| 概念 | 含义 |
|---|---|
| 主对话 | 用户与 Point 的连续交互入口 |
| Goal | 长期意图与期望结果，可跨多次任务推进；具体生命周期待选定插件后统一 |
| Task | 有明确结果的一项工作，保留状态、产物及后续安排 |
| Session / 子 Agent | 执行上下文与执行者，不等同于产品任务本身 |

用户待办也可能是由用户完成的承诺，不意味着 Agent 要执行该动作。Agent 可以围绕它创建内部准备工作。长期目标不是一个永远运行的模型循环；空闲时只保存状态，按事件或计划再判断下一步。

## 已定协作方式

- 主 Agent 处理聊天、查记忆、更新待办与协调工作；复杂工作可委派。
- 子 Agent 按任务创建，同一任务的追问、调整和恢复使用原有执行上下文。
- 独立任务使用独立上下文；完成后停止运行但保留记录，必要时继续。
- 研究、代码、浏览器等是可复用角色配置，不是永久运行的固定成员。
- 子 Agent 完成或遇到阻碍时回传，由主 Agent 结合当前状态处理结果。
- 多个任务可并行，主对话不因等待后台任务而无法响应。
- Agent 可内部拆解步骤，但不能把推断出的每个步骤自动变成用户的新承诺。

主对话与子任务的模型、工具和上下文可分别配置。共享记忆和工作文件不意味着复制全部主对话历史或没有资源冲突。

## SDK 需要补齐的契约

以任务 ID 关联 session、执行尝试、计划、产物和回传记录。具体 schema 待定，不把模型自然语言描述作为唯一运行状态。

- 补充指令区分当前任务调整和后续请求；指向不清时由主 Agent 澄清。
- 取消/改期需要使旧计划和陈旧结果失效；执行前、投递前核对当前任务状态。
- 停止当前回答、停止某个任务、停止所有工作必须是不同作用域。
- 浏览器接手暂停对应资源的自动操作；其他独立工作不必随之停止。
- 重启后不能仅凭会话记录宣称工具成功；外部结果未知时先核查。

## Goal 插件与长期目标的差距

`pi-goal` 类插件已有持久目标与自动继续能力，但“每 session 聚焦一个目标持续执行”不自动等于“多个长期目标按事件择机推进”。需验证如何连接调度、目标焦点与按任务子 Agent。

尚未决定：Goal 是否第一轮即完整交付、目标完成判据、里程碑表示，以及选择哪个插件。切换 SDK 不等于这些插件与产品语义已经选定。
