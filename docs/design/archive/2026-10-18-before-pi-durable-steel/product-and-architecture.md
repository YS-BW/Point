# 产品与 Server / Client 架构

> 已定方向，2026-10-16。产品设计阶段；实现从 Server 开始。

## 产品形态

Point 是一个人的持续工作伙伴，参考 Muse 的主对话、后台工作、工具执行、浏览器与产物形态。它不是只做待办提醒，也不是仅在用户发消息时才工作的 coding agent。

单用户是长期边界。多个客户端共享同一人的状态，不等于多用户。对服务器的访问需要验证本人身份；具体鉴权方式待选，不建设注册、租户或角色系统。

## 职责分配

```text
Web Client（后续可增加 App / 其他入口）
                |
       Point Server（Docker 部署）
         +-- 主对话与 Pi SDK session
         +-- 任务编排与子 Agent sessions
         +-- 目标、计划、记忆与业务状态
         +-- 调度 / 事件触发 / 通知
         +-- 命令、文件、工具与产物
         +-- 持久浏览器与接管通道
```

- Server 是持续工作的主体，关闭网页不停止后台任务。
- Client 负责输入、展示、控制和必要的浏览器接手，不承担定时执行。
- 容器内允许运行命令、读写文件、联网、安装依赖和调用工具。沿用不新增应用内权限层的决定。
- 会话、任务、计划、产物、配置及浏览器 profile 需要持久化。具体目录和数据库待实现前确定。
- Docker 是部署方式，不意味着所有组件必须挤在同一容器。浏览器是否独立服务待选。
- 不默认挂载或控制个人电脑文件与应用；本地节点尚未纳入当前实现承诺。

## 浏览器（已定）

浏览器运行在 Server 端并保留登录状态。Web 提供查看和接手；用户接手时，Agent 必须暂停对相应受控浏览器资源的操作，交还后重新读取状态再继续。

浏览器任务通过专用子 Agent 配置执行。角色配置可复用，任务上下文独立。不同任务对标签页、profile、下载目录的分配和冲突控制需要工程保证；锁粒度与浏览器工具方案尚未选定。

接手登录与验证码是重要场景；具体视频/图像传输、输入协议和凭据处理方式待定。不会仅靠提示词实现人机互斥。

## Web 产品范围（已确认，暂不制作）

| 视图 | 职责 |
|---|---|
| 对话 | 主入口，交代任务、追问和查看结果 |
| 任务 | 展示执行中、等待用户、已安排、已结束的工作，提供停止与继续 |
| 工作区 | 查看、下载文件和产物 |
| 浏览器 | 查看运行状态，接手并交还控制 |

布局倾向主对话常驻，任务详情、文件和浏览器在侧边展开。记忆管理界面与详细决策审计界面后续补充。审计数据需求不因界面后置而消失。

HTTP + SSE 是候选通信方案，尚非已选技术。网页实时事件不等于网页关闭后的系统推送。

## Muse 参考的证据边界

官方已说明：主对话之外有 side chats；可并行处理多项工作，后台工作完成后判断是否通知；浏览器有专用子 Agent，用户接手时暂停 Agent。

未公开或本项目未核实：内部队列、任务优先级、浏览器页面分配及锁实现。Point 的实现不能冒充 Muse 的已知设计。
