# 记忆层与 Durable 适配

> 更新：2026-10-18。记忆自托管、可替换、用户可读可纠正；通过 Pi Durable extension 接入。

## 第一阶段

采用现有 Durable 原型的显式结构化记忆作为实现起点，不以外部记忆系统或 SDK 插件作为运行前提。Point 定义事实/偏好/决定与来源，Durable document 保存权威记录，section 提供受限索引，工具读写详情。

原型的 64 条上限和直接索引注入是验证范围，不是最终容量与检索设计。后台自动抽取、语义检索、完整删除和画像维护尚未交付。

## 后端替换边界

记忆服务必须可自托管；是否调用远程推理模型另行配置。不能因有 Dockerfile 就推断所有功能可自托管，也不能因自托管就推断没有远程数据出口。

OpenViking、TencentDB-Agent-Memory、mem0 等保留为历史候选，未选定或安装。历史对比见[旧版文档](archive/2026-10-16-before-pi-sdk/memory-adapter.md)，实际接入前重新核实能力与版本。Pi Coding Agent 插件只能作为参考，不能直接当作 Durable extension 使用。

替换后必须明确每类记录的权威位置：外部后端拥有内容时，Durable document 只保存 ID、状态和引用；索引/检索缓存是可重建派生数据。不要让两个后端各自修改同一份事实。跨后端写入没有 SQLite 原子性，需持久任务、幂等键与核对机制。

## Point 契约

| 能力 | 要求 |
|---|---|
| 写入/召回 | 接受 Point 的事实结构，返回内容及实际来源，区分无结果与失败 |
| 查看/修订 | 用户可查看、纠正；用户修订不被后台无声覆盖 |
| 遗忘/删除 | 回报处理范围、历史和备份限制，不仅返回成功布尔值 |
| 索引/画像 | 为主/侧/执行会话提供小规模上下文，详细内容按需读取 |
| 恢复/迁移 | 稳定 ID、版本、导出/导入或重建路径，可核对未完成写入 |

来源字段应尽早保留。后续结构可包含 `source_ref`、`asserted_by`、`valid_from`、`valid_until`、`superseded_by`、`confidence`；未知值显式为空，不能以占位字段冒充已实现能力。接口可替换不意味着数据无成本迁移。

## 失败与验收

记忆不可用时聊天可降级，但不能把服务失败当成用户没有约束。凭据与数据出口明确配置，不引入旧方案的通用 taint/egress 审批系统。

先验收显式记忆的跨聊天使用、修订、重启、并发与遗忘；有真实规模需求再比较外部候选。候选需通过 Durable 接入、来源保留、用户纠正、恢复和迁移验证，完整删除不足需明确披露。
