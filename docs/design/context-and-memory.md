# 上下文与记忆

> 更新：2026-10-18。模型上下文、历史与压缩直接使用 Pi Durable；Point 提供角色、环境、会话与记忆内容。

## 原生上下文与产品内容

Durable conversation entries 是会话原始记录的权威来源，活动上下文由其原生投影与压缩机制管理。Point 不维护一份替代性的 messages 数组，不重写工具结果配对或模型—工具循环。

| 内容 | 责任 |
|---|---|
| 历史、工具调用与结果、活动上下文、自动/手动压缩 | Durable 原生能力 |
| 人格、行为规则、能力边界 | Point extension sections / instructions |
| 实际宿主环境、cwd、时间与可用工具说明 | Point 按真实执行环境提供，不能仅配置 cwd 而假定模型已经知道 |
| 当前 main/主题身份、任务要求与版本、相关历史引用 | Point 有界注入或按需检索 |
| 共享记忆索引、用户纠正与时效 | Point 记忆适配器提供，详情通过工具读取 |
| AGENTS/skills 等资源 | 按产品需要显式加载、裁剪并注入；Durable 不自动继承 Pi Coding Agent 的资源发现 |

工具循环与 thinking 配置相互独立。思考级别按模型能力确定并可查看；变更时需处理已有会话的持久配置，不能只改新会话默认值。实际接线与配置证据见[上下文审计](../research/pi-durable-context-audit-2026-10-18.md)。

## main、侧聊与内部执行上下文

main 是长期入口，主题侧聊有独立历史，内部执行会话承接具体任务。主/侧会话可以持续很久，活动上下文超限时使用 Durable 压缩，原始记录仍可分页查询。

委派传递明确任务、相关背景、约束和引用，不默认复制 main 全部历史。fork 必须落在完整消息边界，避免复制未配对工具调用；新话题可 fresh 创建，仅共享明确保存的记忆。聊天关系不等于底层任务 ownership。

回传包含来源聊天/任务、结论、产物和未解决事项。主题同步只把摘要带回 main；摘要不改变原始历史，也不自动升级为长期记忆。浏览器状态通过句柄和最新观察提供，fork 不继承活动浏览器。

## 上下文预算与纠正

稳定的人格和行为规则保持小规模，记忆索引和检索结果控制大小并标明裁剪，详情与原文可按需读取。压缩是缩小活动上下文，不是跨会话长期记忆系统。

用户纠正、任务取消、新截止时间必须及时生效；每次执行/投递还需读取权威状态，不能仅靠旧提示词判断。不能为缓存稳定而保留错误事实。缓存表现取决于提供商和布局，不承诺动态注入一定失效或一定命中。

工具返回与检索内容保留来源；不要把 cookie、访问令牌或浏览器连接凭据注入记忆和聊天。独立任务的工作文件需要目录/写入协调，不能因共享数据就假设没有冲突。

## 记忆的实现起点

先沿用原型的显式记忆：事实、偏好、已确认决定，带来源聊天、类型和更新时间，通过 Durable document 持久化、受限注入。原型最多 64 条；这不是产品长期容量决定，也不是向量检索或自动知识抽取。

后续扩展要求保留来源、用户明说/Agent 推断/外部资料的区分、时效与替代关系。用户编辑优先于后台抽取。长文本、语义检索或自动提炼有实际需要时，再按[记忆适配契约](memory-adapter.md)接入自托管后端。

任务结果、主题摘要、长期记忆分别管理。结构化抽取与压缩可能丢信息，定期回检是候选维护机制，不能保证发现所有漏记。

## 遗忘与删除

当前“忘记”删除保存的记忆条目，停止后续索引注入；原会话、旧摘要与已构建上下文中仍可能有该内容，不宣称彻底删除。

产品需进一步区分“以后别用”与“删除原文及派生数据”，明确摘要、索引、缓存、审计、备份与重新抽取的处理范围。删除完整性未验收前，不同时承诺原文只增不删和删除真删。

## 待验证

- 长历史自动压缩后的关键事实、约束、来源与工具链完整性。
- 多任务检索预算、跨聊天引用与任务状态更新的及时性。
- 并发记忆修订、用户纠正、派生画像和删除范围。
- 任务要求与共享记忆变化后，正在执行的任务如何发现冲突并调整。
