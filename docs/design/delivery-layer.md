# 结果回传与通知

> 更新：2026-10-18。Durable task 保存待交付工作；Point 决定目标会话、展示方式与外部渠道。通知仍是可替换的单向手段。

## 先保存结果，再回到会话

后台工作完成时保存报告、产物引用和业务状态，并在同一 Durable commit 创建待回传任务；生成/写文件的外部阶段需要另行核对。报告成功不代表对话交付或外部通知已经成功。

Report task 以稳定请求 ID 将带来源的结果 `submit()` 到目标 Agent，由目标会话回答，后续追问能够继续使用结果。回传前检查任务当前状态/要求版本，陈旧结果不能冒充完成。任务状态中分别记录执行、会话回传与渠道投递进度。

- 默认回所属聊天；侧聊任务不自动打扰 main。用户要求 main 摘要、或由 main 委派到侧聊时，可同时回 main。
- 归档主题的新路由转入 main，保留来源与原产物；已被模型接收的消息不承诺移动/撤回。
- 主题 Share 是一次显式摘要交付，不合并整段历史，也不自动写长期记忆。
- 结果需要告知与是否外部推送由产品策略区分；外部渠道失败不能让任务产物从 Client 消失。

## Client 展示与同步

主/侧对话展示用户相关结果，任务视图展示详情，工作区展示产物，浏览器视图提供观看/接手。技术审计不必全部变成聊天消息。

初版方向沿用原型 HTTP 指令 + SSE 事件。由 Server 适配 Durable 与产品事件，正式协议需定义稳定 ID、状态版本、分页/游标、流式回答与断线行为。当前原型重连先读快照，历史可分页，不提供无限事件回放。

事件推送是同步提示，持久状态是恢复依据。关闭 Client 不停后台工作；SSE 不等同网页关闭后的 push。浏览器视频/输入使用 Steel 的独立媒体与控制通道，见[浏览器基础设施](browser-infrastructure.md)。AG-UI 可在需要时适配，不作为运行时前提。

## 外部渠道

通知可选择邮件、系统通知、push 等，首个真实渠道尚未决定。不绑定邮箱，不处理邮件回复；第一轮也不接入邮箱等外部数据源。状态更新回到对话入口。

渠道接收稳定通知 ID、内容、任务/要求版本、时效和目标，回报成功、失败、跳过或结果未知。待投递记录与执行任务持久化；本地 sink 仅验证协议，不等于已有真实通知渠道。

- 投递前检查是否完成、取消、改期或已过时。
- 同一逻辑提醒可同时在对话展示和渠道投递，不重复消耗跟进次数。
- 重试复用接收端支持的幂等键。Durable `requestId` 只证明相应内部提交去重，不能证明邮件/push 恰好一次。
- 已发送未保存回执时，支持查询则核对；缺少幂等/查询契约则进入 `unknown`，不盲目重发。
- 发送成功不等于用户已读、认可或任务完成；视频连接存在也不等于用户正在注意。

## 合并、退避与验收

错过提醒按[会话与跟进](conversation-and-followup.md)合并。其他候选的汇总时点与模板待定，不强制每天 Digest 或空汇总。用户暂不考虑免打扰；渠道限流和故障退避独立处理。

需覆盖：报告已保存未回传、提交到会话后未发布 UI、接收端已生效未存回执、取消/改期后旧投递、离线重连与多客户端重建。现有原型已验证其中确定性恢复窗口；真实渠道、周期合并与长期故障仍需验收。
