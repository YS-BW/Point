# 判断层：执行、询问与通知

> 更新：2026-10-18。判断是 Point 的产品策略，经 Pi Durable 执行并持久化。具体模型、分值、预算与接口尚未验证；不把既有调研中的绝对性结论当成已知事实。

## 与 Agent 层的边界

Pi Durable 承担模型与工具循环、上下文、任务和恢复；它不自动决定何时主动联系用户。Point 将时间/事件候选、当前任务版本与证据交给策略，保存决策和后续工作，不另起一套脱离 Durable 的 Agent loop。

判断可作为独立任务或普通执行中的工具/步骤，不要求每次简单聊天都额外调用一次判断模型。策略结果、证据引用与待执行/待投递任务尽量同事务落盘；执行及投递前仍核对最新状态，避免恢复旧决策后推进已取消工作。

当前原型验证的是明确委派、显式记忆和用户安排的一次跟进，尚未验证自主发现目标、自动选择工作或通知节制。不同档模型的路由与成本需分别实测。

## 三种判断

| 时机 | 问题 |
|---|---|
| 执行前 | 是否值得现在花资源推进？信息是否足够？ |
| 执行中 | 是否需要用户输入，能否等到既定提醒？ |
| 执行后 | 是否有值得呈现的新结果，是否需要外部通知？ |

“做不做”与“说不说”是两个维度。旧四档中的 `ACT_THEN_REPORT` 是执行策略，不再把它与通知档位当作同一互斥分类。

候选契约：执行为不执行/现在执行/以后执行；通知为即时/延后汇总/只记录。具体枚举与默认阈值待实现前确定，不预先强制每天发送 Digest。

## 策略边界

模型负责语义理解、相关性、工作量和通知价值判断；系统负责状态转换、计划、去重、取消、预算和投递。已确认的待办默认策略见 [conversation-and-followup.md](conversation-and-followup.md)。

明确用户指令和当前任务状态优先于推断。暂无免打扰规则，不把在线状态判断设为第一版前置条件。提醒时点需可告知和纠正。

可比较 RulePolicy / HeuristicPolicy / ModelPolicy，但不绑定某个“决策模型品类”，也不预先断言非自回归即严格确定性、免费输出或必然低成本。

不新建通用权限或审批层。草稿实际发送由用户决定是已确认行为边界；外部动作的更多具体策略不能从通知分数中自动推导。

## 审计必须区分的情况

- 已看到候选，判断不值得通知。
- 数据源不可用或数据过旧，未能判断。
- 执行失败或被取消，未得到有效结果。
- 决定通知，但投递失败或结果未知。

记录候选关联、使用的证据/状态版本、策略版本、结果、抑制原因和时间。记录模型理由是调试线索，不等同于真实因果解释。

审计只能解释进入候选集的事件；从未识别出来的承诺或事件需要独立评测才能发现。不能宣称沉默日志自动解决选择偏差。

## 预算与评测

注意力预算和执行成本预算分开。全局共享预算的方向保留，但单位、阈值和任务优先级待定。

评测从小规模人工标注的完整事件序列开始，覆盖应该提醒、应该沉默、改期、完成、取消和恢复情形。指标包括重要事件召回、误打扰、漏报、重复通知、时效与成本。

未回复不等于负反馈，投递成功不等于看见或认可。离线回放可先比较策略；在线 A/B 不作为证明改进的唯一方法。回放不应重新执行外部副作用。
